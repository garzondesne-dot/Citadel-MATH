# 스프라이트 · 애니메이션 규격 (코드에서 뽑은 값)

> 근거: `js/engine/art.js` · `assets/manifest.js` · `tools/sprite/cut_grid.py` · `tools/sprite/demagenta.py` · `css/style.css` · `js/raid/hall.js`. 크기는 2026-11-08 `assets/art/*.webp` 를 PIL 로 직접 잼.
> **GPT 는 한 장에 한 프레임만 그린다.** 아래 「시트」는 #4 가 도구로 합친 뒤의 모습이다. 템플릿 칸 선 · 번호 · 기준선은 결과물에 그리지 않는다.

## 1. 게임이 시트를 자르는 방법 (`art.js`)

```js
// cell(sheet, col, row): 시트 한 장을 background 로 깔고 칸 하나만 보이게
background-size: cols*100% rows*100%;
background-position: (100*col/(cols-1))% (100*row/(rows-1))%;
// monster(n, pose): col = poses[pose] (idle 0 · attack 1 · down 2), row = 번호 % rows
//   'mirror:3' = monstersMirror 시트 3번 줄 · '2@h250' = 기본 시트 2번 줄을 hue-rotate 250° (색 변형 돌려쓰기)
//   flip 목록에 있는 줄은 좌우를 뒤집어 그림 (오른쪽을 보고 그려진 그림용)
```

- 그래서 **칸 사이 간격 0 · 모든 칸 같은 크기 · 정확한 격자**여야 한다 → 이것은 #4 의 도구가 맞춘다 (GPT 결과물에 기대하지 않음).
- 화면에서는 칸을 상자에 꽉 채워 그린다 (`.raid2-mon .art.monster { width:100%; height:100% }`). 칸 안 여백이 그대로 화면 여백이 된다.

## 2. 일반 몬스터 · 보스 시트

| 항목 | 일반 몬스터 | 보스 |
|---|---|---|
| 시트 | 3열 × 5줄 (줄 = 몬스터 한 마리 · 차시당 5마리) | 3열 × 1줄 |
| 열(동작) | **0 대기 idle · 1 공격 attack · 2 쓰러짐 down** (`poses: { idle: 0, attack: 1, down: 2 }`) — 동작마다 **1프레임** | 같음 |
| 칸 크기 (실제 게임 값) | **192×192** (`monsters-mirror-v2.webp` 576×960) | **384×384** (`monsters-mirrorboss-v3.webp` 1152×384) |
| 칸 크기 (문서 값) | 원본 96×96 · 8프레임(대기 2 · 공격 3 · 피격 1 · 쓰러짐 2) | 원본 192×192 · 12프레임 |
| 실제 쓰는 프레임 | 3 (피격 · 등장 · 분노 · 흔들림은 코드 연출: `flashRW` · `shake` · `lunge`) | 3 |
| 방향 | 왼쪽을 봄 (`flip` 은 옛 시트 `monsters` 1번 줄만) | 왼쪽 |
| 화면 크기 | 교실 TV: 정사각 상자 `min(46vh, 440px)` · 가운데 · 위 9% / 학생 폰: 150~160px · 오른쪽 6% | TV `min(54vh, 520px)` · 위 7% / 폰 168px |
| 바닥 그림자 | 게임이 그림 (TV 화면 높이 52% 타원) | 같음 |

### 칸 안 자리 (`cut_grid.py` 가 하는 일 = 맞춰야 할 결과)

| 항목 | 값 |
|---|---|
| 크기 | 같은 줄(한 몬스터의 3동작)은 **같은 배율**. 가장 큰 프레임의 긴 변 = 칸의 **94%** |
| 가로 | 칸 가운데 |
| 발 기준선 | 그림 아래끝 = 칸 아래에서 **3%** 위 (192 칸 → y 186 · `bodies` 측정값 0.969) — 모든 프레임 같은 기준선 |
| 피벗 | 발 가운데 (아래 가운데) |
| 칸 사이 | 0 (시트) · 생성 그림에서는 칸을 나누는 **마젠타 틈**이 있어야 자를 수 있음 |
| 빈 칸 | 투명. 없는 동작은 만들지 않는다 (줄마다 3칸 모두 필요) |
| 무기 · 이펙트 | 칸 안에 다 들어올 것 (잘리면 안 됨). 공격 자세가 가장 넓어지므로 대기 자세는 칸보다 작게 보인다 — 정상 |

`tools/pfx/measure_bb.py` 가 대기 칸의 「보이는 몸통 상자」(`bodies`)를 재서 공격 이펙트 · 돌진 자리를 맞춘다. 그림이 바뀌면 #4 가 다시 돌린다.

## 3. 프레임 → 시트 도구 (`tools/sprite/frames_to_sheet.py` · 있음 2026-11-08)

GPT 가 동작별로 따로 만든 PNG 를 #4 가 합친다:

```
python3 tools/sprite/check_frames.py m11-01                     # 자동 검수 표 (먼저)
python3 tools/sprite/frames_to_sheet.py assets/art/monsters-undersea-v1.webp --cell 192 \
    --rows m11-01,m11-02,m11-03,m11-04,m11-05 --png 확인.png    # 시트
```

1. 프레임 고르기: `outputs/{ID}/{ID}_{동작}_1.png` · 다시 만든 판 `_r2` · `_r3` 가 있으면 마지막 판 · **대기 칸 = 마스터 그대로**
2. 마젠타 지우기 (`demagenta.clean`) · 이미 투명이면 그대로
3. 한 줄의 모든 프레임에 **같은 배율** (가장 큰 프레임이 칸의 94%) — 동작마다 키가 다른 것은 자연스러움
4. 가로 가운데 · 발(보이는 아래끝) = 칸 아래 3% 선
5. 마스터에서 뽑은 32색 팔레트로 색 맞춤 (번짐 없이) · 알파 0 / 255
6. 칸 순서 = `--rows`(줄 = 몬스터) × `--actions`(열 = 동작, 기본 idle · attack · down = 배치표 poses 0 · 1 · 2)
7. 시트 webp 저장 → 배치표 등록 → `measure_bb.py`

`check_frames.py` 기준: 정사각 512px 이상 · 배경 마젠타/투명 · 가장자리 3% 여백 · 발 = 아래 3% ±3% · 마스터 대비 키 · 폭 ±5% (공격 키 ±10% · 공격 폭 / 쓰러짐 제외) · 마스터 팔레트 밖 색 10% 이하 · 방향(실루엣 + 세로줄 색 배치로 좌우 뒤집힘 의심). 장비 · 표식은 눈으로.
