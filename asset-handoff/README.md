## 3. 원본 고정 · 동작별 따로 생성 · 붙이기는 도구 (선생님 지침 2026-11-08)

같은 캐릭터를 여러 번 다시 뽑으면 얼굴 · 색 · 비율이 조금씩 틀어진다. 그래서:

| 규칙 | 내용 |
|---|---|
| ① 마스터 1장 먼저 | 캐릭터 · 몬스터마다 **대기(idle) 1프레임만** 먼저 → 선생님 승인 → #4 가 `references/masters/{ID}_master.png` 로 고정. 이 파일이 **유일한 정답지** |
| ② 동작은 한 장에 한 프레임 | 공격 · 쓰러짐 등은 **따로** 만든다. 매번 첨부는 **「마스터 + 템플릿 한 칸」만**. 바로 앞 결과물을 참고로 이어 쓰지 않는다 (**사슬 금지**) |
| ③ 시트 합치기는 도구 | 그림 AI 에게 여러 칸 시트를 그리게 하지 않는다. #4 가 도구(`tools/sprite/frames_to_sheet.py` — **#4 가 만들 도구 · 예정**)로 합친다 |
| ④ 틀어짐 검사 | 마스터와 비교: 실루엣 높이 · 폭 ±5% · 주요 색(머리 · 옷 · 무기)이 같은 팔레트 칸 · 장비 · 표식 유지 · 방향(몬스터 = 왼쪽). 하나라도 어긋나면 「수정 필요」 |
| ⑤ 고칠 때 | 결과물을 덧칠하지 않는다 → **「마스터 + 템플릿」에서 다시 생성**. 같은 프레임 **최대 3번** 다시 만들고, 그래도 안 되면 선생님께 묻는다 |
| ⑥ 게임에 이미 있는 시트 고치기 | 기존 시트의 **대기 칸을 잘라 마스터로** 쓰고, 고칠 칸만 만든다 |

배경 · 아이콘처럼 **한 장짜리**는 마스터 = 결과물 자체 (동작 없음).

## 4. 상태 흐름

| 상태 | 누가 바꾸나 | 뜻 |
|---|---|---|
| 제작 대기 | — | 아직 안 만듦 |
| 생성 완료 | **GPT** | `outputs/{ID}/` 에 파일이 다 있음 (자기 검사 통과) |
| 수정 필요 | 선생님 · #4 | 검사에서 어긋남 → 「마스터 + 템플릿」에서 다시 생성 |
| 승인 완료 | **선생님** | 그림이 마음에 듦 |
| 게임 적용 완료 | **#4 (코드 방) 커밋** | 잘라 · 시트 · webp · 배치표 등록 · 시험 통과 · 커밋 |
| 배포됨 (따로 칸) | 선생님 「배포」 뒤 #4 | 학생 화면에 나감 |

**생성 완료 ≠ 게임 적용 완료.** GPT 는 「생성 완료」까지만 적는다. 마스터 단계는 ASSET_LIST 의 「마스터」 칸(대기 → 생성 완료 → 승인 완료)으로 따로 본다.

## 5. 결과 돌려주는 법

1. 파일은 `outputs/{ID}/{ID}_{동작}_{번호}.png` (이름 규칙: [outputs/README.md](outputs/README.md)).
2. `ASSET_LIST.md` 그 줄의 「마스터」 또는 「상태」 칸만 **생성 완료** 로 바꾼다.
3. 커밋 메시지에 ID 와 만든 파일 목록 · 다시 만든 횟수 · 자기 검사 결과(틀어짐 4항목)를 한 줄씩. main 이 아닌 브랜치(예: `gpt-assets`)에 올린다.
4. 템플릿의 칸 선 · 숫자 · 가이드 · 글자는 **결과물에 절대 그리지 않는다** (템플릿은 배치 확인용).
