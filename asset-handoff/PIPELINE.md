# 생성 → 후처리 → 게임 적용 흐름

> GPT 결과물이 이미 정확한 크기 · 투명 · 격자를 갖췄다고 **가정하지 않는다**. 정확히 맞추는 일은 모두 #4(코드 방) 몫이다.

## 1. 누가 무엇을

| 단계 | 누가 | 하는 일 | 결과 |
|---|---|---|---|
| ① 마스터 | GPT | 대기 1프레임 · 마젠타 배경 · 템플릿 한 칸 배치대로 | `outputs/{ID}/{ID}_idle_1.png` |
| ② 마스터 승인 | 선생님 | 보고 승인 / 수정 필요 | ASSET_LIST 「마스터」 승인 완료 |
| ③ 마스터 고정 | #4 | `references/masters/{ID}_master.png` 로 복사 (원본 그대로) | 정답지 |
| ④ 동작 프레임 | GPT | 동작마다 따로 · 첨부 = 마스터 + 템플릿 한 칸만 | `outputs/{ID}/{ID}_attack_1.png` … |
| ⑤ 자기 검사 | GPT | 아래 「틀어짐 검사」 4항목 · 어긋나면 다시 생성(최대 3번) | ASSET_LIST 상태 「생성 완료」 |
| ⑥ 승인 | 선생님 | 전체 프레임 확인 | 「승인 완료」 |
| ⑦ 후처리 | #4 | 아래 2절 | 시트 webp |
| ⑧ 등록 · 시험 · 커밋 | #4 | 배치표 · 차시 파일 · 시험 · 커밋 | 「게임 적용 완료」 |
| ⑨ 배포 | 선생님 「배포」 → #4 | main 반영 (수업 직전 금지) | 「배포됨」 |

## 2. #4 후처리 (GPT 는 하지 않음)

| 순서 | 도구 | 내용 |
|---|---|---|
| 1 | `python3 tools/sprite/demagenta.py in.png out.png` | 진한 마젠타 → 투명 · 가장자리 분홍 번짐을 외곽선 색 `#1a1228` 쪽으로 정리 |
| 1′ | `python3 tools/sprite/check_frames.py <ID>` | 자동 검수 표: 크기 · 배경 · 여백 3% · 발 기준선 · 마스터 대비 키 · 폭(±5% · 공격 키 ±10% · 쓰러짐 제외) · 팔레트 밖 10% · 방향(뒤집힘). 장비 · 표식은 눈 확인 |
| 2 | `python3 tools/sprite/frames_to_sheet.py <out.webp> --cell 192 --rows <ID,…> --png 확인.png` | 프레임들 → 시트: 대기 = 마스터 · 다시 만든 판(`_rN`)은 마지막 판 · 한 줄 같은 배율(긴 변 94%) · 가운데 · 발 = 칸 아래 3% · 마스터 32색 팔레트 · 알파 0/255 · 칸 순서 = `--actions`(기본 idle,attack,down) |
| 2′ | `python3 tools/sprite/cut_grid.py in.png out.webp <줄> <열> <칸px>` | (옛 방식 · 여러 칸 한 장일 때) 빈 틈으로 줄 · 열 찾기 → 같은 줄 같은 배율 · 긴 변 94% · 발 = 칸 아래 3% 위. 몬스터 칸 192 · 보스 384 |
| 3 | 팔레트 점검 | 색 수 · 외곽선 색 · 분홍 남은 픽셀 확인 (`sheet.py` 는 32색 맞춤 기능이 있음) |
| 4 | webp | 캐릭터 시트 = 무손실 · 배경 = 손실(품질 80~90) · 배경 1600×900 |
| 5 | 이름 · 버전 | 새 파일 이름 `-vN` (예: `dg-09-underwater-v2.webp`). **그림을 바꾸면 이름을 바꾼다** (서비스 워커가 그림을 캐시 먼저로 씀) |
| 6 | `assets/manifest.js` | 시트 등록 (`src · cols · rows · poses · names`) · `art.js SHEETS` 에 'undersea' 같은 짧은 이름 · 차시 파일 `sprite` / `theme` |
| 7 | `sw.js` | 공통 그림이면 STATIC 목록 (차시 던전 그림은 들어갈 때 받음 · `art.js lessonFiles`) |
| 8 | `python3 -I tools/pfx/measure_bb.py` | 몬스터 몸통 상자 `bodies` · 이펙트 범위 `fxbb` 다시 재기 |
| 9 | 시험 | `node tests/lesson.test.js` · `node tests/model.test.js` · `node tests/pwa.test.js` · 해당 차시 시험 · e2e 화면 캡처 |
| 10 | 커밋 | hero-v2 브랜치 · 배포는 선생님 「배포」 뒤 |

## 3. 최종 검사 항목 (#4 · 게임 적용 전)

| 항목 | 기준 |
|---|---|
| 크기 | 시트 = 칸 × 열 · 줄 정확 (몬스터 576×960 · 보스 1152×384 · 배경 1600×900) |
| 투명 | 캐릭터 바깥 알파 0 · 분홍 번짐 0 · 마젠타 남은 픽셀 0 |
| 격자 | 칸 경계를 넘는 픽셀 없음 · 무기 · 이펙트 잘림 없음 |
| 기준선 | 세 동작 발 기준선 같음 (칸 아래 3%) · 가운데 정렬 |
| 방향 | 몬스터 · 보스 왼쪽 |
| 틀어짐 (마스터 대비 · `check_frames.py`) | ① 실루엣 높이 · 폭 ±5% (공격 키 ±10% · 공격 폭 · 쓰러짐 제외) ② 주요 색이 같은 팔레트 칸 ③ 장비 · 표식 유지 ④ 방향 |
| 금지 | 글자 · 숫자 · 가이드선 · 테두리 · 워터마크 없음 |
| 화면 | 교실 TV(1600×900) · 폰(390×844) 캡처에서 몬스터가 배경에 묻히지 않음 · 용사 줄과 겹침 자연스러움 |
| 용량 | 몬스터 시트 ≈ 500KB 이하 · 배경 ≈ 300KB 이하 (지금 수준) |

## 4. 틀어짐 검사 (GPT 자기 검사 = 위 「틀어짐」 4항목)

어긋나면 「수정 필요」 → **결과물을 고치지 않고** 마스터 + 템플릿에서 다시 생성. 같은 프레임 최대 3번 → 그래도 안 되면 선생님께 물음 (어긋난 점을 한 줄로).
