# 결정 목록 (Citadel-MATH)

새 아이디어는 이 목록과 먼저 대조한다. 기존 결정과 부딪히면 반영하기 전에 알린다.
진행 방식: **논의 → 확정안 → "진행"이라고 하면 구현.**
원본(DIMENSION SLASHER)의 결정은 `docs/origin/DS-DECISIONS.md` 에 있고, 따로 바꾸지 않는 한 그대로 따른다.

## ✅ 확정
| 결정 | 이유 |
|---|---|
| DIMENSION SLASHER **본편 v0.3.2** 를 출발점으로 한다 (번외편 「포함의 결계」 아님) | 사용자 지정 |
| 비트는 것은 **게임 방식**, **카드 연성은 살린다** | 사용자 확정 |
| 대상 기기: 스마트폰 | 사용자 확정 |
| 저장·결과 시트를 원본과 분리 (저장 키 `citadel-math-*`, 결과 전송은 시트를 정할 때까지 끔) | 원본 학생 기록과 섞이지 않게 |

## 📌 원본에서 넘어온 대기 안건 (v0.3.2 기준, 아직 구현 안 함)
| 안건 | 내용 | 상태 |
|---|---|---|
| m′ 제한 재고 | m′ 무한 → 소모 부품. 2층 첫 캠프 3개 + 박쥐·거수 보상 1개씩 = 5개, 떨어지면 안내 | 확정안 제시, 승인 대기 (지급량·캠프 지급 여부 질문 남음) |
| 숙련 3번 → 2번 | 원본 확정 결정 변경 | 승인 대기 |
| 마지막 재료 경고창 | 이번 연성으로 0개가 되는 재료가 있으면 경고 (중간·무한 부품·레어 제외, "이번 캠프에서는 그만 묻기") | 승인 대기 |
| 설정창 | 소리·진동·묶음 보기 (치트 모드 넣을지 미정) | 승인 대기 |

## ❓ 미결 질문 (컨셉)
1. **게임 방식을 어떻게 비틀까?** 저장소 이름 Citadel(성채)에서 나온 아이디어 후보:
   - A. 성채 디펜스: 몬스터(문제)가 성으로 내려오고, 연성한 카드를 알맞은 몬스터에 쏘아 막는다. 웨이브 사이에 캠프 연성
   - B. 성채 쌓기: 문제를 풀어 벽돌을 받아 성을 쌓는다 (반 전체 협동 가능)
   - C. 성채 공략: 층을 오르며 성문을 부순다 (원본과 비슷)
2. 단원 범위: 원본처럼 Ⅰ 도형의 방정식(1~4층)인가?
3. 수업 분량(몇 분, 몇 차시)과 11월 3일 수업에서 어디까지 쓰나?
4. 결과·실시간 현황 시트: 원본과 같은 Apps Script 를 쓸지, 새로 만들지
