# 결정 목록 (Citadel-MATH)

새 아이디어는 이 목록과 먼저 대조한다. 기존 결정과 부딪히면 반영하기 전에 알린다.
진행 방식: **논의 → 확정안 → "진행"이라고 하면 구현.**
엔진(DIMENSION SLASHER)의 결정은 `docs/origin/DS-DECISIONS.md` 에 있고, 따로 바꾸지 않는 한 그대로 따른다.

## ✅ 확정
| 결정 | 이유 |
|---|---|
| 게임 기본 형태 = **citadel 교실 레이드**, 엔진 = **DIMENSION SLASHER** | 사용자 지정 ("두 개 짬뽕") |
| citadel 저장소 코드는 **참고만** (복사·수정·푸시 안 함) | 운영 중인 주소·기록 보존 |
| 서버 = **Firebase Realtime Database** (Apps Script 아님) + 이 기기 체험 모드 | Apps Script 는 반응이 너무 느림 |
| 그래픽 에셋을 코드와 분리 (`assets/` + 배치표 `assets/manifest.js`) | 나중에 나만의 에셋으로 갈아 끼우기 |
| 내용은 **집합 3차시 「집합 사이의 포함 관계」** 학습지 부분만. 차시는 하나씩 추가할 수 있게 | 사용자 지정, 기한 없이 차분히 |
| **카드 연성은 살린다** — 엄격 연성 + 처음 만든 카드는 예제를 맞혀야 완성(한 번만) | 사용자 확정 |
| 전투 = **답 제출만** (DS 개인 카드 턴 없음). 카드는 "이 문제에 맞는 카드 고르기"로 쓴다 | 사용자 확정 ("일단 답만 제출") |
| 보스(형성평가) = 폰 입력 자동 채점. 사진·Gemini 채점은 나중에 | 사용자 확정 (추천안) |
| 첫 결과물 = 가상 학생 체험판(`demo.html`) | 사용자 확정 |
| 대상 기기: 학생·교사 = 스마트폰, 종합상황실 = 교실 PC | 사용자 확정 |

## 📏 수업 규칙 (citadel 에서 가져옴, `js/raid/model.js`)
| 규칙 | 내용 |
|---|---|
| 소환 조건 | 참여자(학생 + 교사) 중 그 문제에 맞는 카드가 없는 사람이 있으면 소환 불가 (누가 없는지 알려 줌) |
| 교사 마지막 제출 | 학생 전원이 제출한 뒤에만 교사가 제출 → 바로 판정 |
| 공동 공격 | 교사 포함 전원 정답이어야 성공. 실패하면 같은 유형·새 숫자로 재도전 (벌 없음) |
| 공격력 | 문제를 연 순간 110, 1초에 1씩 줄어 최저 100. 몬스터마다 첫 정답만 점수 |
| 보스 | 형성평가 6문항, 세트1(학습지) → 못 맞힌 문항은 세트2(숫자 바꿈). 문항별 최고 기록, 문항당 100 |
| 최고 용사 | 일반전 + 보스 기여. 동점 추첨, 교사 제외 |
| 개인정보 | 개인 정답·오답은 종합상황실 큰 화면에 띄우지 않는다 (교사 폰·본인 폰에만) |
| 참여 | 교사가 수업 시작 때 참여 명단 확정. 결석·기기 문제는 교사 폰에서 참여 끄기 |
