## 0. 한 줄 요약
**게임 = 수업 플랫폼, 학습지 = 🧩 차시 팩.** 모든 던전은 「입장 → 단계 목록 → 결과」 한 흐름이고, 던전마다 다른 것은 「다른 점 표」 한 장의 값으로만 바꾼다. 완성되면 정식을 한 번에 바꿔치기(「출시」 · 나눠 내지 않음 · 마감 없음).

## 2. 기술 (확정 C②)
- **Vite + TypeScript + Svelte** · GitHub Actions 로 빌드 → Pages. 연출이 필요해지면 PixiJS 를 이펙트 칸에만(첫 한 바퀴엔 없음).
- PWA(설치 · 오프라인) 유지 · 판 번호 = `b1 · b2 …`(테스트) · 「BETA」 띠.
- 서버 = Firebase Realtime Database. 테스트 버전은 **서버에 닿지 않음**(이 기기 저장 · 테스트 모드처럼 바로 시작) — 실시간 시험은 7절 끝.
- 규칙: 모든 데이터 모양(차시 팩 · 학생 기록 · 다른 점 표)은 TypeScript 타입 한 곳(`src/model/`)에. 화면은 상태만 그린다(그리기 함수가 상태를 바꾸지 않음).

## 6. 🧩 차시 팩 (손발 조사 ④ · 후보 1)
- 꼴: `LessonPack { v, id, no, title, steps[], monsters{ id: { sprite, chain?, slots[] } }, boss?, rubrics?, eval? }`
- 칸(Slot) = `{ first: 학습지 문항, retry: { pool: [문항…] } }` (📊 엑셀처럼 미리 써 둔 숫자) **또는** `{ first, retry: { gen: "생성기 이름", params } }` (코드처럼 숫자를 만듦) → 두 종류가 한 꼴에. 생성기는 TS 코드에 이름으로 등록(팩에는 코드가 들어가지 않음 = 보안).
- (b1 에서 고침 · 11/12) 숫자 바꾸기는 소문제 칸이 아니라 **몬스터 단위**(소문제들이 같은 U · A · B 를 함께 씀) · 엑셀 차시는 판 묶음(pool)으로 같은 자리.
- 재도전 = 정식 v3 그대로(틀리면 같은 문제 · 다 맞힌 뒤에만 새 숫자 · 남은 기회 = 연습).
- 숫자 시드 = 방 코드 | 학생 → 폰 · PC가 같은 문제를 각자 만듦(지금 방식 유지).
- 채점 = 지금 `Model.gradeAttempt` · `Quiz.grade` 를 떼어 TS 로 · 독립 검산 시험과 함께.
- 올리기 = 수업 준비 화면 → 자동 검산 → 미리 보기에서 선생님 정답 확인 → 저장.
- 첫 한 바퀴 = 6차시 한 칸만. 2~9차시 옮기기는 ⓓ.

## 7. 서버 데이터 · 기록 이어받기 (A① 확정 · 손발 조사 ③)

| 카드 | `cards/{반}/{번호}/{카드}` |
| 수업 기록 | `records/{반}/{번호}/{차시}` = mons · bossM · loot … |
| 성채 · 허수아비 | `bonus/{반}/{번호}/{차시}/{방}` = clear · tries · mis |
| EXP | `xp/{반}/{번호}` = total · log (레벨은 계산) |
| 그 밖 | surveyDone · photo · 우편(fb · fbr · fgift) · act · qsolve · tester |
- 오답노트 · 얻은 칭호 · 업적은 따로 저장하지 않고 기록으로 계산 → records · bonus · cards · xp 를 지키면 따라옴.
- 옮기지 않음(폰에만 있음): 연성 힌트 점수 · 의견 하루 한도 · 화면 · 소리 설정.
- ⚠ **로그인 계정은 DB 와 따로**(계정 쓰기 규칙이 uid 일치를 확인) → ✅ **로그인 정보까지 통째로 옮김**(비밀번호 그대로 · 1A).
- 💰 경제 자동 이전 (DECISIONS 「💰 경제 변경 규칙」): 산 것마다 `{ id, ver: 산 때의 경제 판 }` 로 저장 · 규칙 표에 판별 이전 표(`migrate[ver] = 옛 칸 → 새 칸`) · 학생이 접속하면 게임이 자기 기록만 새 판으로 옮김(한 번 · 기록 남김 · 우편함 한 줄) · 관리자 일괄 도구 없음 · 값이 바뀐 것은 옮기지 않음(산 것 그대로).
- 옮기는 도구 = 출시 전 미리 보기(몇 명 · 몇 건) → 선생님 허락 → 실행(운영 DB 쓰기 = 선생님이 손발 방에서 직접).
- 실시간 시험 = (가) 화면 · 규칙 회귀 = 같은 기기 두 탭(비용 0) + (나) 폰 ↔ 종합실 실제 동기화 · 출시 리허설 = 시험 전용 Firebase 프로젝트(또는 에뮬레이터) · v1.0 에 「어느 서버」 설정 하나.

선생님 말씀: 「v1.0 은 다른 선생님들에게 배포를 적극 권유할 거야 · 학교판일 때 기본 뼈대와 추가되면 좋을 기능을 구분지어서 개발 · 상대방 선생님이 추가하고 싶은 기능을 쉽게 추가되도록」 → **「결론적으로 학교판(배포판)과 정식판(이 될 v1.0)이 프로그램상 차이가 발생하지 않고 사용자의 선택에 의해 기능이 열리고 잠기게 하는 게 목표」**.

- **목표**: 우리 학교 · 다른 학교 모두 **같은 코드 · 같은 배포**. 다른 것은 그 학교 서버에 저장된 **설정(기능 스위치 + 과목 팩 + 학교 정보)** 뿐. 「학교판 전용 코드」 · 「우리 학교 전용 코드」 없음(`if (학교판)` 금지 → `if (기능 켜짐)`).
- **세 층**

| 층 | 뜻 |
|---|---|
| 🦴 기본 뼈대 | 늘 켜짐 · 어느 과목이든 · 추가 기능을 부르지 않음 |
| 🧩 추가 기능 | 스위치 하나 · 꺼지면 화면에서 통째로 사라짐(오류 0) · 「필요한 것」(과목 팩 · 일과표 · AI 키)이 없으면 잠김 + 채우는 길 안내 |
| 📚 과목 팩 | 단원에 묶인 내용(성취기준 · 오개념 카드 · 기호 톡 · 개념 카드 · OX 문장 · 성채 문항) · 엑셀 양식 · 우리 공통수학2 = 첫 팩 |

- **우리 학교 = 🏰 전체 묶음 + 공통수학2 팩을 켠 한 학교일 뿐**(설정만 다름).
- **묶음(시작값)**: 🪶 기본(뼈대만 · 지금 CLAUDE.md 「🏫 학교판 규칙」 목록 = 이 묶음) · ⚔ 표준(뼈대 + 용사 · 쉼터 놀이 · 몬스터 공격) · 🏰 전체(과목 팩 있을 때). 고른 뒤 낱낱이 스위치로 더하고 뺌. 화면 = 교사 「나」 탭 「⚙ 우리 학교 기능」.
