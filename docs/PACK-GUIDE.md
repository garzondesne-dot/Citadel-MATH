# 📦 차시 팩 만들기 지침 v2 (다른 AI에게 주는 글) — 2026-11-14 · 머리 방

> 이 글을 다른 AI에게 그대로 준다. AI는 학습지를 보고 「차시 팩」 JSON 한 파일을 만든다. 선생님이 베타 교사 폰 「준비 → 도구 → 📦 차시 팩 올리기」에 올리고, 검사를 통과하면 저장된다.
> **v2 기준 = 앱에서 실제로 저장에 성공한 11차시 팩**(2026-11-14). 칸 이름 · 자료형은 모두 이 파일을 따른다.

## 1. 원칙
- 학습지의 문제 · 보기 · 정답 · 숫자를 바꾸지 않는다(버전 0 = 학습지 원문).
- 정답은 직접 계산해 확인한다. 계산으로 확인할 수 없는 문항(문장 · 증명)은 검산 표에 「눈으로 확인」.
- 배경 · 몬스터 · 보스 이름은 **8절 도감 목록에 있는 ID만** 쓴다. 지어내지 않는다.
- 출력 = JSON 한 덩어리(설명 문장 금지) + 맨 뒤 검산 표.

## 2. 맨 위 칸 (자료형은 통과 예시 그대로)
| 칸 | 자료형 | 예 | 규칙 |
|---|---|---|---|
| `id` | 글자 | `"ex-11"` | 영어 소문자 · 숫자 · - 만 |
| `no` | 숫자 | `11` | 차시 번호 |
| `title` · `unit` · `goal` | 글자 | | 학습지 그대로 |
| `theme` | 글자 | `"12-skygarden"` | **8-1 던전 배경 ID 중 하나** |
| `steps` | 목록 | 3절 | 수업 순서 |
| `mons` | 묶음 | 4절 | 몬스터 단계마다 하나 |
| `boss` | 묶음 | 5절 | 형성평가 하나 |
| `img` | 목록 | `[]` | 비워 둠(그림은 선생님이 zip 으로) |
| `video` | 목록 | `[]` | 비워 둠(영상은 다음 단계) |
| `pct` | 숫자 | `100` | 100 |

## 3. steps (수업 순서)
`{ "kind": 종류, "id": 칸 이름, "title": 제목, "say": "말할 거리(선택)", "img": "그림 칸(선택)" }`
| kind | 뜻 | id 예 |
|---|---|---|
| `intro` | 도입(전시 확인 · 생각 열기) · `"img": "review"` | `intro` |
| `concept` | 개념 칸 · 오늘 정리 | `c1` · `c2` · `recap` |
| `monster` | 문제 칸 하나 = 몬스터 하나 | `m1` · `m2` … |
| `boss` | 형성평가(맨 끝 하나) | `sum` |
- `monster` 단계의 id 마다 `mons` 에 같은 이름의 항목이 꼭 있어야 한다.

## 4. mons (문제 칸)
```json
"m1": { "title": "문제 1 · 거울 웅덩이 두꺼비", "sprite": "garden4:0", "vers": [ [ 문항, 문항, … ] ] }
```
- `sprite` = **8-2 몬스터 도감 ID** + `:0` (예: `"garden4:0"`).
- **몬스터 그림을 정하기 어려우면 앱 기본값 `"base0:0"`**(수정 슬라임)을 쓴다. 빈 칸 `""` 은 쓰지 않는다.
  예: `"m3": { "title": "문제 3", "sprite": "base0:0", "vers": [ [ … ] ] }`
- `vers` = 버전 목록. 지금은 **버전 0 하나만**: `[[ 문항들 ]]`.

## 5. boss (형성평가) — 가장 많이 틀린 곳
```json
"boss": {
  "title": "형성평가 · 필요충분의 천칭 수호자",
  "sprite": "gardenboss0:0",
  "items": 5,
  "hpItems": 5,
  "tags": ["c1", "c1", "c2", "c2", "c1"],
  "vers": [ [ 문항1, 문항2, 문항3, 문항4, 문항5 ] ]
}
```
| 칸 | 자료형 | 규칙 |
|---|---|---|
| `sprite` | 글자 | **8-2 도감 ID**(보스는 `…boss0:0` · `crown…:0` · `base2:0` 권장) |
| `items` | **숫자**(목록 아님) | = 그 차시 **버전 0 형성평가 문항 수** — 차시마다 실제로 센다 |
| `hpItems` | **숫자**(목록 아님) | 체력 문항 수 · **1 이상 items 이하** (보통 items 와 같게) |
| `tags` | 글자 목록 | **개수 = items** · 문항 순서대로 그 문항이 묻는 개념 칸 id(`c1` · `c2` …) · steps 에 있는 concept id 만 |
| `vers` | 목록 | `[[ 문항 × items ]]` |

## 6. 문항 한 개 (모든 칸을 다 씀)
`{ "type": …, "q": "문제", "a": "정답", "ch": [보기], "sol": "풀이 한 줄" }`
| type | `a` (늘 **글자**) | `ch` |
|---|---|---|
| `choice` 선다 | 보기 번호(0부터) `"1"` | 보기 목록 필수 |
| `multi` 여러 개 | `"0,2"` | 보기 목록 필수 |
| `ox` | `"O"` 또는 `"X"` | `[]` |
| `number` | 정수 `"12"` | `[]` |
| `blanks` 빈칸 | 칸 순서대로 `"홀수,홀수"` · `"P,Q,R"` | `[]` |
| `text` 단답 · 문장 | `"답1\|답2"` | `[]` |
- 보기가 없는 문항도 `"ch": []` 를 쓴다.

## 7. 출력 전 스스로 검사 (하나라도 아니면 고친 뒤 출력)
| # | 검사 |
|---|---|
| 1 | **boss.items = 버전 0 형성평가 문항 수 = tags 개수** |
| 2 | **1 ≤ boss.hpItems ≤ boss.items** · items · hpItems 는 숫자 |
| 3 | theme 가 8-1 목록에 있다 |
| 4 | 모든 sprite 가 8-2 목록 ID + `:0` 이고 빈 칸이 없다(모르면 `"base0:0"`) |
| 5 | steps 의 monster id 마다 mons 항목이 있다 · boss 단계가 맨 끝에 하나 |
| 6 | tags 의 값이 모두 steps 의 concept id 다 |
| 7 | choice · multi 의 a 가 보기 번호 범위(0 ~ 보기 수 − 1) 안 · 다른 type 은 `"ch": []` |
| 8 | 학습지 원문 숫자와 한 글자도 다르지 않다 |
