# ✏ 출제 공방 · AI 판단 지시문 (머리 · 2026-11-18) — 중계소(사진 채점과 같은 길)에 「출제 분석」으로 더함

## 들어가는 것
1. 학생 사진 = 양식 **뒷면**(이름 띠는 앱이 가림 · 모서리 표시 4개로 반듯하게 펴서 보냄)
2. 학생이 앱에서 고른 바탕 방 id(예: eval-1/q04) → 그 방 **첫 판** 문제 글 · 정답(성채 팩 그대로)
3. 학생이 앱에서 고른 「객관식 / 주관식」 · 「무엇을 바꿨나」 체크

## 할 일 (순서대로)
1. **옮겨 적기**: 내 문제 · 보기(객관식) · 정답 · 풀이 ①~⑤ · 힌트 · 몬스터 이름 → 글 · 식만(수식은 게임 표기 · 예 x², √2, A ∩ B). 읽을 수 없으면 `unreadable` 로 끝.
2. **바탕 비교**: 학생 문제와 바탕 방 문제를 나란히 놓고 같은 단원 개념 · 같은 뼈대인지 본다. **바탕과 관계없는 문제(다른 단원 · 다른 뼈대 · 문제집 문제로 보임) = ⚪ `not_from_base`**.
3. **두 번 따로 풀기**: 풀이를 보지 않고 1번 · 다른 방법으로 2번. 두 답이 같고 학생 정답과도 같아야 통과. 다르면 ⚪ `wrong_answer`(어디가 다른지 한 줄).
4. **풀 수 있나**: 답이 하나인지 · 조건이 서로 부딪히지 않는지(예: n(A ∩ B) > n(A)) · 배운 개념(공통수학2 집합과 명제)만 쓰는지 → 아니면 ⚪ `unsolvable`.
5. **등급**:
   - 🟢 `green` = 숫자만 바뀜(뼈대 · 묻는 것 · 조건 그대로)
   - 🔵 `blue` = 조건 · 묻는 것 · 형식(객관식 ↔ 주관식) 중 하나 이상 바뀜 · 같은 개념
   - 🟣 `purple` = 새 상황 · 새 이야기 · 다른 개념과 새로 연결(후보일 뿐 · 결정은 선생님)
   - ⚪ `gray` = 반려(이유 코드: not_from_base · wrong_answer · unsolvable · unreadable · inappropriate)
6. **학생 체크와 비교**: 학생이 고른 「무엇을 바꿨나」와 실제가 다르면 한 줄(예: 「숫자만 바뀐 것 같아요 · 조건도 바꿔 보세요」).
7. **몬스터화**(🟢 🔵 🟣): 게임 문제 형식(객관식 = 고르기 5 · 주관식 = 숫자 / 글 입력) · 정답 · 💡 힌트(학생 힌트 · 없으면 AI 한 줄) · 풀이 단계(학생 ①~⑤를 다듬음) · 몬스터 이름(학생 것 · 부적절하면 바꿈).

## 내놓는 것 (JSON 하나)
`{ grade, reason, base:{room}, type:'obj'|'subj', problem, choices[5]?, answer, steps[], hint, monster, solve1, solve2, agree, selfCheckNote, issues[] }` — 사진 · 이름은 저장하지 않음.

## 예시 (바탕 = 🏰 1층 04 : n(A) = 16, n(B) = 21, n(A ∪ B) = 28 일 때 n(A ∩ B))
| 등급 | 학생 문제 | 판단 |
|---|---|---|
| 🟢 | n(A) = 20, n(B) = 15, n(A ∪ B) = 30 일 때 n(A ∩ B) | 숫자만 → 정답 5 |
| 🔵 | n(A) = 16, n(B) = 21, n(A ∩ B) = 9 일 때 n(A ∪ B) | 묻는 것이 바뀜 → 28 |
| 🔵 | 위 바탕을 객관식 5지로 · 보기 ① 7 ② 8 ③ 9 ④ 10 ⑤ 11 | 형식 바뀜 → ③ |
| 🟣 | 우리 반 35명 중 축구 좋아함 20명, 농구 좋아함 18명, 둘 다 안 좋아함 5명 → 둘 다 좋아하는 학생 수 | 새 상황 + 여집합 연결 → 8 |
| ⚪ not_from_base | x² − 5x + 6 = 0 의 두 근의 합 | 바탕과 다른 단원 |
| ⚪ unsolvable | n(A) = 5, n(B) = 7, n(A ∩ B) = 9 일 때 n(A ∪ B) | n(A ∩ B) 가 n(A) 보다 큼 |
| ⚪ wrong_answer | 🟢 문제에 정답 6 | 두 번 풀이 = 5 |
