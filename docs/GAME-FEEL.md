# 게임 손맛 · 스킬 아이디어 학습 노트 (2026-11-06 · 사용자 자료 학습)

> 사용자가 준 「HTML5 게임 완성도를 높이는 무료 스킬 · 시스템 아이디어」 + pixelfx 영상 요약을 **우리 게임 기준**으로 따진 것.
> 새 연출 · 스킬을 고를 때 이 표의 판단 기준을 먼저 본다. 실제 넣는 것은 늘 「확정안 → 진행」 뒤.

## 0. 판단 기준 (우리 게임의 고정 규칙 — DECISIONS)

| 규칙 | 연출 · 스킬에 주는 제한 |
|---|---|
| 몬스터 = 문제 · **데미지 = 맞힌 소문제 수** | 스킬이 데미지 · 체력 · 정답 판정을 바꾸면 안 됨 → **연출(보이는 것)만** 바꾼다 |
| 실패해도 벌 없음 · 재도전은 숫자만 바꿔서 | 틀렸을 때 연출은 「튕겨냄 · 빗나감」까지. 깎기 · 잠금 · 놀림 금지 |
| 게임 기록은 성적이 아니다 · 공정 | 근접 / 원거리 · 이펙트 단계에 따라 보상 차이 없음. 시간 제한을 스킬로 늘리거나 줄이지 않음 |
| 빌드 도구 없는 HTML5 (`<script>` 순서 · `window.DS`) | 큰 엔진(Phaser · PixiJS) 도입은 구조를 갈아엎는 일 → 하지 않음 |
| 대상 기기 = 학생 폰 · 교실 TV(종합상황실, 25명 동시) · 학교 PC | 동시 25명 연출이 가벼워야 함 · WebGL 필수 기능은 피함 |
| 그림은 `assets/manifest.js` · 캐시 이름 = 버전 | 새 그림은 파일 이름에 v 번호 · sw CORE 등록 |

## 2. 방어 · 유틸리티 스킬 → 우리 게임으로 옮기면

| 아이디어 | 원래 뜻 | 우리 게임에서 | 판단 |
|---|---|---|---|
| **시간 왜곡** (deltaTime × 0.3) | 적 · 탄만 느리게 | **마지막 일격 슬로모션 0.4초** (처치 순간만 화면 연출 속도 ↓). 문제 풀이 시간 · 보스 타임바에는 절대 안 씀 | ✅ 채택 (처치 연출) · ❌ 풀이 시간 조절은 금지 |
| **대시 분신** (순간이동 + 잔상) | 이동하고 제자리에 미끼를 남김 | **근접 10명 돌진 잔상**: 달려갈 때 반투명 잔상 2~3개가 남았다 사라짐 (CSS 복제 · 가벼움) | ✅ 채택 (근접 연출에 바로 포함) |
| **반사 장막** (탄 벡터 × −1) | 적 탄을 되돌려 보냄 | 🏰 성채의 「몬스터 공격(45초마다 1초 멈춤)」에 **연속 정답 3번 → 방패가 생겨 다음 공격 1번을 튕겨냄**(멈춤 없음 + 반사 연출). 보상이지 벌이 아님 | 🔍 제안 단계 (게임 규칙이 조금 바뀌므로 사용자 확정 필요) |

## 4. 우리 게임의 「손맛」 한 판 순서 (지금까지 합의한 것 + 이 노트)

1. 공격 동작 시작 (근접 = 돌진 + 잔상 / 원거리 = 공격 줄 + 탄 발사 · 유도 곡선)
2. 맞는 순간 = 고른 이펙트 + **멈칫(히트스톱 0.03~0.14초)** + 화면 흔들림 + 몬스터 밀림 + 데미지 숫자 「−1」
3. 연속 정답 → 이펙트 크게 · 「n연속!」 · (다음 판) 협동 연쇄 빛줄기
4. 처치 · 퍼펙트 → 슬로모션 0.4초 + 충격파 + 몬스터 쓰러짐 + 💎 · EXP 가 용사에게 날아와 머리 위 표시
5. 틀림 → 몬스터가 튕겨냄 · 탄 빗나감 (벌 없음)

숫자 기준: 히트스톱은 pixelfx act 의 `freeze`(가벼운 공격 0.03 · 무거운 공격 0.14~0.2초) · 흔들림 `shake 0.18초 · amp 2px` · 밀림 `push 2.8px`(우리 화면 배율로 키움). 한 공격 전체 약 0.8초 (근접 · 원거리 같게).
