`docs/DECISIONS.md` 의 2026-10-31 결정(카드 → 대장간, 공동 체력 레이드, 계정, 수업 흐름, 학습지 v4)을 코드로 옮기는 계획.

## 1. 구현 순서 (단계별)

### 1단계 · 수업 엔진 개편 (레이드) — v0.2.0 ✅ 완료 (2026-10-31)
| 항목 | 내용 |
|---|---|
| 3차시 v4 차시 묶음 | 수업 순서: 도입 → 개념1 → 문제1(필드 1, 4칸) → 보강(스페셜 1, 3칸) → 개념2 → 문제2(필드 2, 3칸) → 개념3 → 문제3(필드 3, 6칸) → 보강(스페셜 2, 4칸) → 형성평가(보스) |
| 문제 | 세트1 = 학습지 그대로. 재도전 = 소문제 전부 새 숫자(틀린 칸 표시). 보스 세트1(학습지) · 세트2(숫자 바꿈, 7번 새 문항 2⁶⁻³ = 8) |
| 입력 방식 | 선다형(⊂/⊄, =/≠) · 다이얼(숫자) · 골라 담기(문제3 줄마다 후보 집합, 함정 2개) |
| 판정 (`model.js` 새로) | 몬스터 체력 = ⌊대기실 인원 × 소문제 수 × 기준%⌋ − 데미지. 전원 1회 이상 제출 뒤 판정. 미제출자는 교사 ▶ 두 번으로 제외. 보스 체력은 1~6번 기준, 7번 보너스 |
| 학생 폰 | 내 캐릭터 vs 몬스터 1마리 대치. 체력 칸 = 소문제 수. 결과: 공격 성공 / 실패 / 부분 성공(3/4) → "다시 해 보겠습니까?" (2번까지) |
| 종합상황실 | 개념 설명 = 학습지 이미지 화면 절반. 전투 = 캐릭터 전원 이동, 실패는 물렁한 소리, 성공은 타격 + 몬스터 빨강·하양 번쩍 + 체력 실시간 감소. 보스 등장 연출(땅 흔들림) |
| 교사 폰 | **◀ 뒤로 / 앞으로 ▶** + 도움 필요 학생(직접 요청 · 연속 오답 · 오래 미제출) + 몬스터별 기준% 실시간 조정 |
| 수업 준비 화면 (PC) | 단계별 학습지 이미지 올리기(Firebase Realtime Database, 줄인 이미지) · 기준% 기본값 |
| 없애는 것 | 수업 중 연성 단계·필드 단계, 카드 고르기, 소환 카드 조건, 공격력 110→100, 최고 용사, 선생님 마지막 공격 |
| 입장 | 이 단계에서는 지금처럼 수업 코드·QR + 번호·닉네임 (계정은 2단계) |
| 테스트 | `lesson.test.js` (v4 세트1·재도전 생성기·보스 세트2 검산), `model.test.js` (체력·기준%·데미지 증가분·전원 제출·보스 즉시 승리·미제출 제외), `pwa.test.js` |

### 2단계 · 계정 — v0.3.0 ✅ 완료 (2026-10-31)
| 항목 | 내용 |
|---|---|
| 명단 | 수업 준비 화면에서 반·번호·이름 명단 올리기 (저장소에 안 넣음) |
| 가입·로그인 | 반 + 번호 선택 → 로그인 전엔 가린 이름(김*우), 로그인 뒤 전체 이름. 비밀번호 숫자 4자리. 중복 가입 막음 |
| 초기화 | 교사 [초기화] → 학생이 0000 으로 로그인 → 새 로그인을 기존 데이터에 연결 → 새 4자리로 바꾸기 |
| 보안 규칙 | 학생은 자기 데이터만, 교사는 반 데이터. 명단 전체 이름은 로그인한 같은 반만 |
| 종합상황실 | 캐릭터 머리 위 번호·이름 |
| 교사 계정 | 교사 폰을 다른 기기에서도 이어서 쓰기 |
